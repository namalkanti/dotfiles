# UAV Runner Specifications

This reference defines invocation formulas, context-passing mechanisms, and feature capabilities for UAV-supported autonomous runners.

## Supported Runners Overview

| Runner | Binary | Session ID Tracking | In-Session / Fork | Jev Co-Processor | Default Invocation Mode |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Pi** *(default)* | `/usr/bin/pi` | `--session-id <uuid>` | Yes (`--fork`) | Yes (`jev_decide`) | Tmux new window (or in-session) |
| **Claude Code** | `/usr/bin/claude` | `--session-id <uuid>` | No (external) | No | Tmux new window |
| **Codex CLI** | `/usr/bin/codex` | No (external daemon) | No (external) | No | Tmux new window |

---

## 1. Pi Runner (Default)

Pi is the primary runner, supporting full integration with Pi extensions (`jev_decide`), deterministic session tracking, and file expansion.

### Invocation Pattern (Tmux)
```bash
tmux new-window -n "uav:<task>" -c "<workspace-dir>" \
  "pi --session-id <uuid> @<mission-file>; exec bash"
```

### Options & Flags
- `--session-id <uuid>`: Deterministic UUID generated by parent before dispatch. Allows parent to inspect session transcript directly at `~/.pi/agent/sessions/`.
- `@<mission-file>`: Directly loads markdown mission brief into the initial turn.
- `--fork <session-file|id>`: (Optional) Fork the parent session into the isolated workspace.
- `--model <pattern>`: (Optional) Select specific model for task requirements.

### Jev Integration
- Pi runner has access to `jev_decide` via `~/.pi/agent/extensions/jev.ts`.
- Mission briefs for Pi include explicit Jev trigger rubrics for anti-spiral detection and ambiguity resolution.

## 2. Claude Code Runner

Claude Code runs out-of-band for deep exploration or standalone Anthropic agent runs.

### Invocation Pattern (Tmux)
```bash
tmux new-window -n "uav:<task>" -c "<workspace-dir>" \
  "claude --session-id <uuid> --permission-mode auto \"\$(cat <mission-file>)\"; exec bash"
```

### Options & Flags
- `--session-id <uuid>`: Deterministic UUID for the Claude conversation.
- `--permission-mode auto` (or `acceptEdits`): Autonomous tool execution without blocking on interactive confirmation.
- Mission brief passed as initial prompt string from `<mission-file>`.

### Tooling Differences
- Does not have access to Pi extensions (`jev_decide`). Any Jev instructions must be stripped from the mission brief.

---

## 3. Codex CLI Runner

Codex CLI provides an alternative autonomous agent backend.

### Invocation Pattern (Tmux)
```bash
tmux new-window -n "uav:<task>" -c "<workspace-dir>" \
  "codex -s workspace-write -a never \"\$(cat <mission-file>)\"; exec bash"
```

### Options & Flags
- `-s workspace-write`: Confines write permissions to the targeted workspace/worktree.
- `-a never`: Autonomous tool execution without human confirmation gating during execution.
- `-C <dir>`: Explicit working directory override (if not using `tmux -c`).

### Tooling Differences
- Does not have access to Pi extensions (`jev_decide`). Jev instructions must be stripped from the mission brief.

---

## Tmux Session Safety Rules

1. **Keep Shell Alive**: Always terminate tmux commands with `; exec bash`. If the runner crashes or completes quickly, the pane remains open for user review.
2. **Window Naming**: Format window names as `uav:<task-slug>` for easy recognition and navigation in tmux.
3. **Workspace Anchoring**: Always supply `-c "<workspace-dir>"` to `tmux new-window` to ensure the runner spawns directly inside the target worktree.
