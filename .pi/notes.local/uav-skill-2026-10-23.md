# UAV Skill: Autonomous Task Dispatch Orchestrator

**Date**: 2026-10-23  
**Status**: Completed

## Summary
Designed, implemented, and verified `uav`, a self-contained Pi skill for dispatching autonomous or exploratory agent runs with strict ceremony, non-destructive isolation, and structured debriefing. Supports multi-runner execution across `pi` (default), `claude`, and `codex`.

## Architecture & Design Decisions
- **Skill implementation**: Implemented as a Pi skill (`~/.pi/agent/skills/uav/` tracked in dotfiles) with dedicated reference documents for runners, flight plans, worktree operations, and Jev playbooks.
- **Multi-Runner Support**:
  - `pi`: Primary runner with deterministic session tracking (`--session-id <uuid>`), `@mission.md` syntax, session forking (`--fork`), and calibrated `jev_decide` co-processor integration.
  - `claude`: Out-of-band Anthropic runner with `--permission-mode auto`.
  - `codex`: Out-of-band runner with `-s workspace-write -a never`.
- **Workspace Topologies**:
  - Isolated git worktree in `/tmp/uav-<repo>-<task>-<timestamp>` on branch `uav/<task>` (default).
  - In-place current working directory (`cwd`) for read-only or immediate edits.
  - Mission briefs (`/tmp/uav-<task>-mission.md`) and debriefs (`/tmp/uav-<task>-debrief.md`) always reside in `/tmp` to keep project trees pristine.
- **Execution Surface**: Dedicated tmux window (`tmux new-window`) with shell preservation (`exec bash`) so users can inspect output even if the agent finishes or errors out.
- **Teardown Lifecycle**: Tmux windows, temporary worktrees, and branches are cleanly torn down only after the user reviews the debrief and approves the work.

## Critical Files
